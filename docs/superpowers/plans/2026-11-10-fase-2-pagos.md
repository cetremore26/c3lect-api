# Fase 2 — Pagos y webhook de MercadoPago — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** que ningún pago cobrado por MercadoPago se pierda: el webhook procesa antes de responder y es reintentable, cada `approved` termina en pedido o en alerta al admin, y el stock se verifica bien antes de cobrar.

**Architecture:** `HandleWebhookUseCase` deja de tragarse errores. Valida la firma (si falla, `UnauthorizedError` → 401) y procesa cada `approved` en una sola `uow.run` (transición del pago, pedido, `linkToOrder`, `PagoAprobado`). Si algo esperado del negocio falla (`DomainError`), la transacción se revierte, el pago se marca `APROBADO` en una segunda `uow.run` y se publica `PagoSinPedido`. Cualquier otro error se propaga y el controller responde 500, así MercadoPago reintenta. Las transiciones del pago las decide una regla de dominio (`reglaDeTransicion`) y el repositorio las aplica con un `updateMany` condicional. El PDF del comprobante pasa a notificaciones (`after-commit`).

**Tech Stack:** NestJS 11, Prisma 6 (Postgres), Jest 30, SDK `mercadopago` 3, `pdf-lib`, pnpm.

**Spec:** `docs/superpowers/specs/2026-11-10-correcciones-revision-design.md` (sección "Fase 2 — Pagos y webhook de MercadoPago", 2.1–2.4).

## Review Focus

1. **Las dos notificaciones de un mismo pago** (MercadoPago manda `payment.created` y `payment.updated`). Si un `approved` ya terminó en `PagoSinPedido`, la segunda entrega no repite la alerta ni intenta crear el pedido. Test en la Task 6: fila `APROBADO` con el mismo `mpPaymentId` → no se publica nada.
2. **El admin reembolsa el cobro duplicado.** Llega un `refunded` del pago duplicado (Y) sobre una fila `APROBADO` con X. La fila no pasa a `REEMBOLSADO` y no se manda alerta de reembolso del pedido. Tests en las Tasks 2 y 6 (`exigeMismoMpPaymentId`).
3. **Un rechazo después de una aprobación.** Un segundo intento rechazado en otra pestaña no pisa `APROBADO`. Tests en las Tasks 2 y 6: la regla de `RECHAZADO` no incluye `APROBADO` y no se cancela nada.
4. **`ts` de `x-signature` en milisegundos (13 dígitos)**, que es como lo envía MercadoPago en producción, o en segundos, como en su documentación. Ambos valen dentro de la ventana. Una `v1` de otra longitud devuelve `false` sin lanzar (`timingSafeEqual` lanza con longitudes distintas). Tests en la Task 1.
5. **Falta `MP_WEBHOOK_SECRET`.** Es un fallo de configuración, no una firma inválida: responde 500 (no 401), así MercadoPago reintenta y el pago se procesa cuando se configure el secreto. Test en la Task 6.
