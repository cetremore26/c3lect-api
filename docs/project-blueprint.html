01 · QUÉ ES

Una tienda, un backend de negocio.

El repositorio concentra las capacidades que convierten la vitrina de productos en una operación comercial trazable.

Verificado

Solución

API REST NestJS organizada como monolito modular. Los bounded contexts separan identidad, catálogo, pedidos, pagos, operaciones y analítica.

Documentado

Contexto

C3LECT comercializa relojería y perfumería premium desde Medellín. El frontend “Bóveda C3LECT” aparece enlazado en el README, pero vive fuera de este workspace.

Idea central · El pago aprobado dispara un pedido confirmado y sus efectos de inventario/ventas dentro de una transacción coordinada por eventos.
02 · PROBLEMA → SOLUCIÓN

Del catálogo a la operación.

La implementación conecta el camino del cliente con controles de stock, auditoría y conciliación comercial.

Comprar no termina en una URL de checkout: debe dejar stock, ventas, comprobante y trazabilidad consistentes.

Presiones que el código resuelve

Evitar pedidos huérfanos antes de aprobar un pago, limitar el checkout al stock disponible, aislar responsabilidades por contexto y no enviar correos de operaciones revertidas.

Pedidos invitadosWebhook idempotenteEventos after-commit
03 · CÓMO FUNCIONA

Checkout sin residuos.

Flujo principal trazado desde `POST /payments/create-pending` y el webhook firmado de MercadoPago.

01 · COTIZAR

Items y precio

Orders consulta catálogo, promociones e inventario para construir el total.

02 · CONGELAR

Draft de pago

Se guarda `Payment` pendiente con el carrito, envío y referencia externa.

03 · CONFIRMAR

Webhook

Se verifica firma, se protege contra reintentos y se procesa en segundo plano.

04 · TRANSACCIONAR

Pedido + stock

El pedido confirmado, inventario y ventas comparten la unidad de trabajo.

05 · NOTIFICAR

Después del commit

Correo, voucher y Meta reaccionan sin bloquear ni celebrar un rollback.

Evidencia: `payments/application/use-cases`, `orders/application/use-cases`, `shared/infrastructure/events` y suscriptores de inventario, ventas, notificaciones y Meta.

¿Qué no podemos afirmar?

No se verificaron pantallas, responsive layout, hover states, mouse interactions, navegación real ni el catálogo visual del frontend. Este Blueprint usa interacción propia de documentación, pero no la presenta como UX de la tienda.

Fuente externa citada en README: Bóveda C3LECT · GitHub Pages.
